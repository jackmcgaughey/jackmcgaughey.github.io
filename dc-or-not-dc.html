The part I got wrong last time

The first version of this never got used. It was a reporting tool that was worthless until enough people reported, which meant it was worthless when the first person opened it, which meant there was never a second person. I built the tool and assumed the adoption.

This rebuild starts from the opposite end: the page has to be useful with zero contributors. Everything below is in service of that.

01 Answer without data

Occupancy is mostly predictable — a Tuesday 2pm in the Fishbowl looks like every other Tuesday 2pm. A per-space time-of-day prior gives a real answer before anyone has ever reported. Reports correct the prior; they aren't the only thing holding it up.

02 One building, not a campus

The old version covered every study space on campus, which split thin traffic across dozens of rooms so nothing ever looked fresh. Scoping to DC concentrates the same number of reporters into six spaces, where a handful of people per hour is enough to stay live.

03 Reporting costs nothing

One tap, four choices, no account, no confirm step, no permission prompt. You report from the chair you're already sitting in. If it costs more than the five seconds it saves someone else, it doesn't get done.

04 Stale data expires loudly

A report decays with a 25-minute half-life and is dropped after three hours. The interface always says which spaces are running on live reports and which are running on the model — a confident wrong answer is what kills trust.

How the number is actually computed 
prior(zone, t)   = base(zone) x hourCurve(t) x dayFactor(t) x examFactor

weight(report)   = 0.5 ^ (ageMinutes / 25)        dropped past 180 min

occupancy       = ( SUM w(i) x level(i) + Wp x prior )
                  -----------------------------------
                       ( SUM w(i) + Wp )          Wp = 0.9

liveShare       = SUM w(i) / ( SUM w(i) + Wp )

One fresh report roughly matches the prior's weight, so a single person can move the number without a lone mistaken tap overwhelming it. Three fresh reports and the crowd owns the answer. liveShare is what drives the live / predicted label on each space.

Reports are stored in your browser only — this is a working demo of the design, not a live deployment.  ·
